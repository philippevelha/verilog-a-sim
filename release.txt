verilog-a-sim — release log
===========================

Versioning, from 0.9.0 onward:

  * Every integrated feature or fix bumps the patch: 0.9.0 -> 0.9.1 -> 0.9.2 -> ...
  * Each bump gets a dated entry below with a sentence or two saying what changed.
  * 1.0.0 is reached when the remaining 1.0 blockers (see the "Road to 1.0" list at
    the bottom) are closed. Until then the version stays in the 0.9.x range.
  * The version lives in the workspace Cargo.toml (`[workspace.package] version`);
    every crate inherits it with `version.workspace = true`. Bump both together —
    the number in this file and the one in Cargo.toml must always agree.

Newest first.


0.9.6 — 2026-09-06
------------------
`cross`'s `time_tol`/`expr_tol` are honoured, by a bracketing retry loop. A candidate step
that reveals a crossing it has overshot by more than the requested tolerance is rejected
and re-taken, aiming just past the interpolated crossing, through the same retry path the
LTE controller already uses. Aiming past rather than at the crossing is deliberate: the LRM
requires the event to fire after it, and landing a hair before would hide it.

  `EventSink::monitor` gained a `CrossTol` argument to carry the request. A signature
  change rather than a defaulted companion, for the reason the analysis context was one --
  a consumer that ignores a tolerance is silently failing to honour something the source
  asked for, so no implementor should be able to miss it.

  Measured convergence: ~70 ulps of the timescale -- a 1e-18 s tolerance really is met at
  t = 83us, where f64 spacing is ~1.4e-20 s. Below that spacing it cannot be, and the count
  is reported through `Waveform::unresolved_events` and warned about at the end of the run,
  rather than quietly missed. The blanket compile-time warning from 0.9.5 is gone, being
  no longer true.

  A site that requests no tolerance never brackets, so every pre-existing run is
  bit-identical: 27/27 golden circuits unmoved.

  724 tests, 27/27 golden circuits, corpus steady at 113/132, clippy and fmt clean.


0.9.5 — 2026-09-06
------------------
Stop dropping event arguments. The parser kept only the first two arguments of
`cross`/`timer` and silently discarded the rest, which included `enable` -- whose entire
job is to switch the event off, so a model that disabled an event got it firing anyway.
All arguments now reach elaboration, which interprets them positionally per event kind
and rejects a count the LRM does not define.

  `enable` is honoured: a disabled site registers nothing, so it cannot fire, and it is
  re-evaluated every accepted timepoint since it may switch during a run.

  `cross`'s `time_tol`/`expr_tol` are recorded on the IR and **warned about**. This engine
  fires at the accepted timepoint ending the bracketing step, so resolution is set by the
  timestep rather than by the requested tolerance -- a model asking for 1ns on a 2us step
  gets 2us. Carrying them means the bracketing retry loop that fixes this needs no further
  interface change. A `timer`'s `time_tol` raises no warning: the LRM asks for a timepoint
  within it and the integrator lands exactly, so it is already satisfied.

  Fixed along the way: with `enable` honoured, a disabled site stops reporting, and the
  consumer had been reading "no report" as a value of 0.0 -- which would compare against
  whatever the site last reported and fire the event precisely because it was switched off.
  Unreported slots are now distinct from zero.

  722 tests, 27/27 golden circuits, corpus steady at 113/132, clippy and fmt clean.


0.9.4 — 2026-09-06
------------------
`@(timer(...))` works, and the IR's event sites are unified. `va_ir::Module::cross_sites`
becomes `event_sites: Vec<EventSite>` with `Cross`/`Timer` variants and `Expr::CrossFired`
becomes `EventFired`, so slot numbering is one flat space across event kinds -- the
consumer's fired-flag buffer indexes it and must not care which kind claimed a slot.
Interface beta gains `EventSink::timer(slot, next)`, defaulted to forward to `breakpoint`:
a breakpoint only says "stop here", while a firing must say which event fires there.

  A model re-registers its next occurrence at every accepted timepoint, so it stays
  stateless about its own schedule -- the arithmetic is a pure function of
  (start, period, now). Period defaults to 0, the LRM's "fire once".

  Stated limitations: bare form only (a compound `initial_step or timer(...)` is still
  refused, as are `above` and `absdelta`); an occurrence landing on the run's *initial*
  timepoint is not delivered, that point being a seed rather than a solved step; tolerance
  arguments are parsed and discarded.

  718 tests, 27/27 golden circuits, corpus steady at 113/132, clippy and fmt clean.


0.9.3 — 2026-09-06
------------------
`@(cross(...))` bodies actually run. Interface beta gains the event channel's notification
half (`ModelState::event_fired`), `va-ir` gains `CrossSite` + `Expr::CrossFired`, the
parser and elaborator turn `@(cross(e, dir)) stmt` into a registered monitored site plus a
guarded body, and codegen reports the expression and reads the firing back. The integrator
re-solves the timepoint once firings are known, because the body changes the equations.

  Corpus back to 113/132 module-declaring files (95/99 self-contained), recovering the
  seven verilogaLib-master clocked blocks 0.9.1 refused -- they now genuinely work rather
  than latching at every solve point.

  Bare form only: a compound `initial_step or cross(...)` is still refused, and so are
  `final_step`, `timer`, `above` and `absdelta`. The body runs at the accepted timepoint
  ending the bracketing step, not at the interpolated crossing time inside it; the two
  tolerance arguments are parsed and discarded.

  711 tests, 27/27 golden circuits, clippy and fmt clean.


0.9.2 — 2026-09-06
------------------
Interface beta gains an event-registration channel (a section 6 coordinated change):
`EventSink` + `CrossDir` in va-abi, and two defaulted `ModelInstance` methods,
`event_count`/`events`. A model can now tell the transient engine which expressions to
watch for a zero crossing and which absolute times to solve at; `va-transient` polls it
once per *accepted* timepoint -- never during Newton, never for a rejected candidate --
detects and times crossings into `Waveform::model_crossings`, and lands exactly on a
model-requested breakpoint.

  It is a separate channel rather than more calls on `StampSink` because of cadence: a
  registration is a statement about the trajectory, and `load` runs per Newton iteration
  and per rejected step. `bound_step` rides `load` only because it is identity-free.

  Registration only. The channel does not yet carry *notification* back into `load`, so an
  `@(cross(...))` body still cannot run at the firing timepoint and the 0.9.1 refusal
  stands. That is the next step, and it lifts the refusal.

  706 tests, 27/27 golden circuits, clippy and fmt clean.


0.9.1 — 2026-09-06
------------------
Event-trigger refusal. `@(...)` triggers other than `initial_step` used to be discarded,
running their body unconditionally -- so `@(cross(V(clk) - vt, 1)) ...` executed at every
solve point instead of on the edge, silently. Monitored triggers (`cross`, `above`,
`timer`, `absdelta`) are now refused at parse time, because they never fire in a static
solve either and so were wrong in every analysis; step-scoped ones (`final_step`,
`initial_instance`, `initial_model`) are refused only in a transient run, since running
them once in a static solve is correct.

  Corpus cost, stated plainly: 113/132 -> 107/132 module-declaring files (95/99 -> 89/99
  self-contained). The seven newly-failing verilogaLib-master files are all clocked blocks
  built on `@(cross(V(clk) ...))` -- a D flip-flop that latches at every solve point was
  never really passing. The count returns when `cross` is genuinely scheduled.

  697 tests, 27/27 golden circuits, clippy and fmt clean.


0.9.0 — 2026-09-06
------------------
Baseline. First numbered release; the workspace had been sitting at 0.0.0 since
bootstrap. Everything below this line is the state that number describes, measured
rather than asserted.

  Verified at this version:
    - 694 tests passing, 0 failed, 0 ignored (`cargo test --workspace`)
    - 27/27 golden circuits vs real QSPICE, convergence 27/27 (`cargo xtask validate`)
    - `cargo clippy --workspace --all-targets -- -D warnings` clean; `cargo fmt` clean
    - Corpus: 113/132 module-declaring files pass frontend + codegen; 95/99 of the
      self-contained ones (`va-cli check external --codegen`, 171 files scanned)
    - 21 Quarto tutorials

  What works end to end: DC operating point and `.dc` sweep, transient with adaptive
  timestep and LTE control, small-signal AC, and noise (output, input-referred, and
  per-device attribution) — each driven through the real Verilog-A frontend -> codegen
  -> core pipeline from a SPICE-style deck, and each gated against committed QSPICE
  golden output. All six bring-up-ladder rungs pass.

  Language: the full Verilog-A grammar is the target and most of it is in — module
  hierarchy and instantiation, the discipline/nature system including user-defined
  disciplines, contributions, ddt/idt, the analog control-flow set, analog functions,
  genvar/generate, vector nets and ports, array variables, ddx, the Laplace/Z filter
  family, and the three noise builtins. `docs/token-reference.md` is the token-by-token
  record.


Road to 1.0
-----------
Tracked in docs/roadmap.md; listed here so the release log is self-contained.

  [ ] Analog events. `@(initial_step)`, `@(cross(...))` and `@(timer(...))` all work as
      of 0.9.4. Still refused, and each needing its own work: `final_step`, `above`,
      `absdelta`, and compound triggers (`initial_step or cross(...)`). `above` is the
      cheapest of those -- semantically a one-sided `cross`, whose machinery, tolerances
      and bracketing all now exist.
      See roadmap "Analog events: what exists, and what each one still needs".

  [ ] absdelay / laplace_* in transient. Currently refused rather than folded (as of
      0.9.0), which is honest but not implemented. Lifting the refusal is
      docs/proposals/absdelay.md stage 2.

  [ ] Decide the sparse-solve question for the shipped configuration. The production
      path is dense LU; the project's own benchmark measured sparse winning 12-33x
      above ~20 nodes. Either wire it or state the circuit-size limit in the release.

  [ ] Close the remaining expired-premise items ($mfactor from a deck's `m=`,
      $simparam against the real NewtonConfig values, $limit's model-declared
      junctions). See roadmap "Expired premises: a standing review".
